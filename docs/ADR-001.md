# ADR-001: Código estándar de ubicación de productos
**Fecha:** 2026-10-01
**Estado:** Aceptado
**Decisores:** Ángel Alberto González Flores (PO), Miguel Angel Lobo Nicolas (SM), Edgar Adrian Uribe Presas, Orlando Fabian Fierros Garrido, Erik Damian Guardado Rodriguez
**Consultados:** Deborah Leticia Villaseñor Basulto (Profesora / Facilitadora)
---
## Contexto
La Papelería Los Piwis maneja una gran variedad de artículos y el propietario presenta dificultades para conocer con precisión cuántas unidades hay de cada producto y en qué parte exacta del local se encuentran almacenados. Esto provoca tiempos excesivos recorriendo pasillos, un aprovechamiento ineficiente del espacio y complicaciones para detectar desabastos. Actualmente los productos se organizan de forma tradicional por categorías, lo cual no permite una localización rápida ni priorizar según la demanda. El sistema debe permitir buscar un producto por nombre o código y obtener su ubicación exacta mediante pasillo, anaquel y estante dentro del plazo del MVP.
---
## Decisión
<!-- ¿Qué se decidió? Ser específico y directo. -->
**Decidimos:** Adoptar un código jerárquico estándar de tres niveles (`P{n}-A{n}-E{n}`) para identificar la ubicación física de cada producto en el local, almacenando los niveles en columnas separadas en la base de datos.
---
## Justificación
<!-- ¿Por qué se tomó esta decisión? ¿Qué razones la respaldan? -->
1. **Mapeo directo con los requisitos:** Cumple exactamente con las historias de usuario (HU-1 y HU-5) que exigen mostrar pasillo, anaquel y estante.
2. **Consistencia y validación:** El uso de un formato estructurado y validado mediante expresiones regulares evita variantes informales y asegura datos limpios.
3. **Facilidad de consulta y filtrado:** Separar los campos en la base de datos permite filtrar por pasillo o anaquel de forma eficiente para apoyar la reorganización por demanda.
4. **Bajo costo de implementación:** Es una solución sencilla y directa que se adapta perfectamente a la capacidad del equipo de 140 horas para el MVP.
5. **Fácil adopción operativa:** Un código corto es fácil de recordar, registrar por el propietario y rotular físicamente en los estantes del local.
---
## Consecuencias
<!-- ¿Qué implica esta decisión? ¿Qué se gana? ¿Qué se sacrifica?
¿Qué habrá que hacer a partir de ahora? -->
### Consecuencias positivas ✅
- Búsqueda rápida y exacta de productos, cumpliendo el objetivo principal del MVP.
- Datos estructurados que facilitan reportes de inventario y rotación.
- Lenguaje común y estandarizado entre el sistema informático y el local físico.
### Consecuencias negativas ❌
- Se requiere un esfuerzo inicial de rotulado físico en la papelería y registro exhaustivo de la ubicación de cada artículo.
- Dependencia de la disciplina operativa: si un producto cambia de lugar físicamente y no se actualiza en el sistema, la información será errónea.
### Acciones derivadas 📝

- [ ] Definir el plano físico de pasillos, anaqueles y estantes de la papelería.
- [ ] Configurar la validación del formato de código en el backend y base de datos.
- [ ] Registrar la ubicación inicial para todos los productos del inventario base.
---
## Alternativas Consideradas
<!-- ¿Qué otras opciones se evaluaron? ¿Por qué se descartaron? -->
### Alternativa 1: Organización exclusiva por categoría
**Descripción:** Mantener la distribución tradicional basada únicamente en la categoría del producto.
**Razón para descartarla:** No indica una posición exacta ni permite optimizar la búsqueda o la reorganización basada en la demanda.
### Alternativa 2: Ubicación como texto libre
**Descripción:** Permitir al usuario escribir la ubicación en formato de texto libre (ej. "arriba del estante 2").
**Razón para descartarla:** Genera inconsistencias, errores tipográficos y dificulta cualquier filtrado o búsqueda automatizada confiable.
### Alternativa 3: Coordenadas o mapa interactivo avanzado
**Descripción:** Implementar un plano gráfico interactivo con coordenadas espaciales completas.
**Razón para descartarla:** Excede el tiempo disponible del MVP (140 horas) y la complejidad técnica no se justifica en esta primera etapa.
