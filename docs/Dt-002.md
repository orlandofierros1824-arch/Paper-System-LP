# 🔴 DT-002: `Ausencia de Pooling de Conexiones en la Base de Datos MySQL`

| Campo | Detalle |
|-------|---------|
| **Descripción** | Las peticiones HTTP que interactúan con MySQL abren y cierran conexiones individuales por cada consulta, lo que degrada el rendimiento bajo carga concurrente. |
| **Ubicación** | `backend/database.py` |
| **Impacto** | 🔴 Alto |
| **Prioridad** | 🔴 Alta |
| **Solución propuesta** | Implementar un gestor de conexión persistente y pool de conexiones utilizando `SQLAlchemy` o el conector nativo optimizado. |
| **Esfuerzo estimado** | `M` |
| **Responsable** | `Edgar Adrian Uribe` |
| **Fecha de registro** | `2026-10-01` |
| **Estado** | `Pendiente` |

---

## 📌 Detalle Técnico
Al no reutilizar las conexiones con MySQL, el tiempo de respuesta del servidor aumenta conforme más empleados realizan consultas simultáneas de ubicación de productos en la papelería.

## ✅ Criterios de Aceptación
- [ ] Reemplazar la conexión plano a plano por un pool configurado en `database.py`.
- [ ] Validar el cierre correcto de sesiones y manejo de excepciones de conexión saturada.
- [ ] Monitorear el tiempo de respuesta de las consultas bajo simulación concurrente.
