# ADR-002: Selección de Python para el Backend y MySQL para la Base de Datos
**Fecha:** 2026-10-05
**Estado:** Aceptado
**Decisores:** Ángel Alberto González Flores (PO), Miguel Angel Lobo Nicolas (SM), Edgar Adrian Uribe Presas, Orlando Fabian Fierros Garrido, Erik Damian Guardado Rodriguez
**Consultados:** Deborah Leticia Villaseñor Basulto (Profesora / Facilitadora)
---
## Contexto
<!-- ¿Cuál era el problema o necesidad?
¿Qué situación nos llevó a tomar esta decisión?
¿Qué restricciones teníamos (tiempo, presupuesto, conocimiento del equipo)? -->
Para el desarrollo del sistema de gestión de inventario de la Papelería Los Piwis, fue necesario establecer una arquitectura que permitiera publicar la aplicación web y mantener disponible la información almacenada en la base de datos.

Inicialmente, el desarrollo se realizó mediante tecnologías web como HTML, CSS y JavaScript, con el propósito de construir una interfaz que permitiera consultar y gestionar la información del inventario. Sin embargo, también surgió la necesidad de contar con un entorno de alojamiento externo que facilitara el acceso a la aplicación y permitiera mantener la información centralizada, sin depender exclusivamente de un equipo local.

Debido a estas necesidades, se consideró utilizar servicios en la nube para el despliegue de la aplicación y el almacenamiento de la base de datos, buscando facilitar la disponibilidad del sistema, la comunicación entre sus componentes y el acceso remoto a la información.

---
## Decisión
<!-- ¿Qué se decidió? Ser específico y directo. -->
Decidimos: Utilizar Render como plataforma de despliegue de la aplicación y Aiven como servicio de alojamiento de la base de datos MySQL.

La interfaz web se desarrolló utilizando HTML, CSS y JavaScript, mientras que la base de datos se alojó en Aiven para permitir conexiones remotas desde el entorno de aplicación.

Esta arquitectura permite separar la presentación de la información, el procesamiento de las solicitudes y el almacenamiento de los datos.

---
## Justificación
<!-- ¿Por qué se tomó esta decisión? ¿Qué razones la respaldan? -->
1. **Disponibilidad mediante Render:** Se seleccionó Render como plataforma de alojamiento para publicar la aplicación y permitir que los usuarios puedan acceder a ella mediante Internet, sin depender de que el proyecto se ejecute exclusivamente desde una computadora local.

2. **Almacenamiento en la nube con Aiven:** Se utilizó Aiven para alojar la base de datos MySQL, permitiendo centralizar la información y acceder a ella de manera remota desde el entorno de aplicación.

3. **Separación de componentes:** La arquitectura permite mantener diferenciados los archivos de la interfaz web y los servicios encargados de procesar las solicitudes y consultar la información almacenada.

4. **Acceso remoto a la información:** Al utilizar una base de datos alojada en la nube, se evita depender de una instancia local de MySQL para consultar y gestionar los datos del sistema.

5. **Facilidad de mantenimiento:** La separación entre la aplicación y la base de datos facilita realizar modificaciones en la interfaz y administrar la información sin tener que mantener todos los componentes en un único equipo.
---
## Consecuencias
<!-- ¿Qué implica esta decisión? ¿Qué se gana? ¿Qué se sacrifica?
¿Qué habrá que hacer a partir de ahora? -->
### Consecuencias positivas ✅
- Disponibilidad de la aplicación mediante una plataforma de alojamiento en la nube.
- Acceso remoto a la base de datos MySQL alojada en Aiven.
- Centralización de la información correspondiente al sistema de inventario.
- Separación de la interfaz web y el almacenamiento de los datos.
- Menor dependencia de un servidor local para acceder a la información.
- Posibilidad de mantener y actualizar los componentes del sistema de manera independiente.
### Consecuencias negativas ❌
- Dependencia de la disponibilidad de los servicios externos Render y Aiven.
- Necesidad de mantener correctamente configuradas las credenciales y los parámetros de conexión.
- Dependencia de una conexión a Internet para acceder a los servicios alojados en la nube.
- Necesidad de controlar los permisos de acceso y proteger las credenciales de la base de datos.
- Posibles limitaciones relacionadas con los recursos y condiciones del plan de alojamiento utilizado.
### Acciones derivadas 📝

- [ ] Mantener configurada la conexión entre la aplicación y la base de datos MySQL de Aiven.
- [ ] Verificar que la aplicación desplegada en Render pueda comunicarse correctamente con la base de datos.
- [ ] Configurar las variables de entorno necesarias para proteger las credenciales de conexión.
- [ ] Verificar las operaciones de consulta, registro, actualización y eliminación de información.
- [ ] Documentar la estructura de la base de datos y sus relaciones.
- [ ] Comprobar el funcionamiento de la aplicación después de cada actualización del proyecto.
- [ ] Establecer medidas para proteger la información y evitar accesos no autorizados.

## Alternativas Consideradas
<!-- ¿Qué otras opciones se evaluaron? ¿Por qué se descartaron? -->
### Alternativa 1: Node.js (Express) con MongoDB
**Descripción:** Utilizar JavaScript tanto en el backend como base de datos NoSQL orientada a documentos.
**Razón para descartarla:** Aunque unifica el lenguaje con el frontend, la estructura altamente relacional del inventario y las ubicaciones (pasillo-anaquel-estante) se modela de forma mucho más rigurosa y segura en tablas relacionales con MySQL.
### Alternativa 2: PHP con MySQL
**Descripción:** Desarrollar el backend utilizando PHP clásico o con un framework como Laravel.
**Razón para descartarla:** El equipo prefiere y encuentra mayor versatilidad y modernidad en el ecosistema de Python para la construcción de APIs RESTful conectadas al frontend de React.
### Alternativa 3: Base de datos en memoria o archivos JSON
**Descripción:** Almacenar la información en archivos locales o estructuras en memoria sin motor de base de datos.
**Razón para descartarla:** No garantiza la persistencia confiable, el control de concurrencia ni las transacciones ACID necesarias para un sistema de inventario real.
