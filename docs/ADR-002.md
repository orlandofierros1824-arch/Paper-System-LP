# ADR-002: Selección de Python para el Backend y MySQL para la Base de Datos
**Fecha:** 2026-10-05
**Estado:** Aceptado
**Decisores:** Ángel Alberto González Flores (PO), Miguel Angel Lobo Nicolas (SM), Edgar Adrian Uribe Presas, Orlando Fabian Fierros Garrido, Erik Damian Guardado Rodriguez
**Consultados:** Deborah Leticia Villaseñor Basulto (Profesora / Facilitadora)
---
## Contexto
<!-- ¿Cuál era el problema o necesidad?
¿Qué situación nos llevó a tomar esta decisión?
¿Qué restricciones teníamos (tiempo, presupuesto, conocimiento del equipo)? -->
Para el desarrollo del sistema de gestión de inventario de la Papelería Los Piwis, necesitamos definir la arquitectura del servidor (backend) y el sistema de gestión de base de datos que respaldarán la aplicación web. El proyecto debe completarse en un periodo de 10 a 17 semanas, con una capacidad de equipo limitada a 14 horas semanales. Requerimos una solución tecnológica sólida que permita manejar operaciones de inventario, control de existencias, registro de ventas y autenticación segura de usuarios (dueño, empleados y administradores) manteniendo la integridad relacional estricta de los datos.
---
## Decisión
<!-- ¿Qué se decidió? Ser específico y directo. -->
**Decidimos:** Utilizar **Python** como lenguaje para el desarrollo del backend de la aplicación y **MySQL** como el sistema de gestión de base de datos relacional, implementando autenticación basada en tokens JWT.
---
## Justificación
<!-- ¿Por qué se tomó esta decisión? ¿Qué razones la respaldan? -->
1. **Modelo relacional robusto en MySQL:** Las entidades del sistema (productos, existencias, ubicaciones, ventas y usuarios) poseen relaciones claras y estrictas que se adaptan perfectamente a un esquema relacional con transacciones ACID para evitar inconsistencias en el inventario.
2. **Agilidad y legibilidad con Python:** Python ofrece un desarrollo rápido, sintaxis clara y una amplia variedad de librerías y frameworks que se ajustan eficientemente a las limitaciones de tiempo del equipo.
3. **Integración y despliegue estándar:** MySQL y Python cuentan con una excelente compatibilidad con plataformas de despliegue en la nube y documentación abundante.
4. **Seguridad y escalabilidad con JWT:** El uso de JSON Web Tokens (JWT) permite gestionar sesiones seguras y sin estado para el inicio de sesión del propietario y administradores de forma eficiente.
---
## Consecuencias
<!-- ¿Qué implica esta decisión? ¿Qué se gana? ¿Qué se sacrifica?
¿Qué habrá que hacer a partir de ahora? -->
### Consecuencias positivas ✅
- Integridad transaccional garantizada para el control de existencias y ventas.
- Desarrollo ágil del backend gracias a la simplicidad y potencia de Python.
- Autenticación segura y desacoplada mediante tokens JWT.
- Arquitectura estándar y fácil de mantener para futuras ampliaciones del sistema.
### Consecuencias negativas ❌
- Se requiere asegurar la correcta configuración y conexión del servidor backend con la base de datos MySQL en el entorno de despliegue cloud.
- Necesidad de definir y aplicar un sistema de migraciones de base de datos para mantener sincronizados los cambios de esquema en el equipo.
### Acciones derivadas 📝

- [ ] Configurar el entorno de desarrollo backend en Python.
- [ ] Diseñar el diagrama entidad-relación (DER) e implementar el esquema inicial en MySQL.
- [ ] Implementar los endpoints de autenticación con JWT y gestión de productos y ubicaciones.
---
## Alternativas Consideradas
<!-- ¿Qué otras opciones se evaluaron? ¿Por qué se descartaron? -->
### Alternativa 1: Node.js (Express) con MongoDB
**Descripción:** Utilizar JavaScript tanto en el backend como base de datos NoSQL orientada a documentos.
**Razón para descartarla:** Aunque unifica el lenguaje con el frontend, la estructura altamente relacional del inventario y las ubicaciones (pasillo-anaquel-estante) se modela de forma mucho más rigurosa y segura en tablas relacionales con MySQL.
### Alternativa 2: PHP con MySQL
**Descripción:** Desarrollar el backend utilizando PHP clásico o con un framework como Laravel.
**Razón para descartarla:** El equipo prefiere y encuentra mayor versatilidad y modernidad en el ecosistema de Python para la construcción de APIs RESTful conectadas al frontend de React.
### Alternativa 3: Base de datos en memoria o archivos JSON
**Descripción:** Almacenar la información en archivos locales o estructuras en memoria sin motor de base de datos.
**Razón para descartarla:** No garantiza la persistencia confiable, el control de concurrencia ni las transacciones ACID necesarias para un sistema de inventario real.
