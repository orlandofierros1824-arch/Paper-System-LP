# 🟡 DT-003: `Falta de validación estricta y saneamiento de entradas en el Backend`

| Campo | Detalle |
|-------|---------|
| **Descripción** | Los datos recibidos en los formularios de registro de productos y códigos de ubicación (`P-A-E`) no pasan por un esquema de validación robusto antes de insertarse en MySQL. |
| **Ubicación** | `backend/controllers/` o `validators.py` |
| **Impacto** | 🟡 Medio |
| **Prioridad** | 🟡 Media |
| **Solución propuesta** | Integrar una librería de validación como `Pydantic` o `Marshmallow` para asegurar la integridad de los datos de entrada. |
| **Esfuerzo estimado** | `S` |
| **Responsable** | `Erik Damian Guardado` |
| **Fecha de registro** | `2026-10-01` |
| **Estado** | `Pendiente` |

---

## 📌 Detalle Técnico
Sin validación estricta en el servidor, existe riesgo de inyección o de ingreso de formatos de ubicación inválidos que rompan la consistencia del código jerárquico `P{n}-A{n}-E{n}`.

## ✅ Criterios de Aceptación
- [ ] Definir esquemas de validación para la creación y actualización de productos.
- [ ] Retornar códigos de error HTTP `400 Bad Request` ante entradas malformadas.
